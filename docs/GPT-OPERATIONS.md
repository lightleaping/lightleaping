# GPT로 포트폴리오 운영하기

각 프로젝트 대화에서 구현·학습하고, 전체 조율 대화에서 아래 기록을 모아 갱신합니다. 다른 대화의 내용이 자동 공유되었다고 가정하지 않고 파일·커밋·요약을 전달합니다.

## 1. 새 포트폴리오 관리 대화의 첫 프롬프트

```text
이 대화는 내 GitHub 포트폴리오 운영·면접 준비 조율용이다.
GitHub: https://github.com/lightleaping
프로필 문서 저장소: https://github.com/lightleaping/lightleaping

먼저 최신 README, docs/STATUS.md, docs/INTERVIEW-GATE.md와 내가 전달한 작업 기록을 읽어줘.

가장 중요한 원칙:
기존 GitHub 프로젝트는 다시 공부하거나 면접 준비에서 제외해야 한다.
코드·README·과거 성능 수치가 있다고 내 현재 역량으로 인정하지 말아줘.
직접 재구현, 설명, 실행 재현, 변경 과제 리뷰 전까지 대표 성과·지원서·면접 답변에서 제외해줘.
내가 이해했다고 말한 것과 코드·설명 리뷰로 확인한 것을 구분해줘.

현재 프로젝트:
1. 실제 상품 기반 코디 추천·보드: 가상 착용 제외, 가짜 상품을 필수 단계로 두지 않음.
2. 사례 기반 이상탐지·원인 분석 Agent: 하드웨어·XR 제외, 소프트웨어 시나리오 사용.
   Agent·자동 원인 분석·설명·보고서 필수. 실험을 논문 형식으로 정리.
3. Structured Bloom: Streamlit 재구현. React/JavaScript 직접 개발 제외.
   Python 추천 로직, 단계적 FastAPI·DB·AI 기능 연결.
4. 세계관 캐릭터 엔진: 페르소나·기억·상태·허용 행동과 평가.
5. 공통 기본기: 필요한 Python·PyTorch 등을 작은 코드로 복구.

작업 방식:
- 내가 직접 구현하고 설명하는 학습이 목적이다.
- 프로젝트를 임의로 합치거나 범위를 제거하지 않는다.
- 확인한 사실 / 사용자 설명 / 미검증 / 계획을 구분한다.
- 미측정 수치, 가짜 실행 결과, 확인하지 않은 기여·기간을 만들지 않는다.
- 과거 자료를 새 프로젝트의 검증 증거로 전용하지 않는다.
- 비공개 코드·개인 자료를 공개 문서에 그대로 옮기지 않는다.
- 저장소 존재·공개 접근을 확인하지 않은 코드/데모 URL을 만들지 않는다.
- 사용자 승인 없는 주기 실행이나 자동 게시를 설정하지 않는다.

매번 현재 상태, 이번에 바꿀 문서, 증거, 다음 미션을 정리해줘.
기존 저장소 삭제·이름 변경·공개 범위 변경은 별도 요청 없이 하지 말아줘.
```

## 2. 각 프로젝트 대화에서 미션 종료 시 요청

```text
이번 작업을 포트폴리오 조율 대화에 전달할 수 있게 요약해줘.
완료 여부는 실제 결과를 기준으로 판단하고 아래 항목을 채워줘.

- 프로젝트와 미션:
- 내가 직접 작성/수정한 부분:
- 기존 코드·AI 도움을 사용한 부분:
- 코드 파일 또는 커밋:
- 실행 명령·환경·입력:
- 실제 결과와 실패:
- 내가 설명한 내용과 리뷰 결과:
- 독립적인 변경 과제와 결과:
- 데이터/평가 조건과 미검증 부분:
- 공개할 수 있는 자료:
- README에 쓸 수 있는 사실 한 문장:
- 다음 미션:

파일을 생성한 것과 구현·이해가 완료된 것을 구분해줘.
```

## 3. 주간 갱신 요청

```text
첨부한 이번 주 작업 기록만을 새 증거로 사용해 포트폴리오를 갱신해줘.
먼저 기록 사이의 충돌과 누락을 확인해줘.

1. docs/STATUS.md의 구현·실행·설명·면접 상태를 각각 갱신한다.
2. 해당 프로젝트 문서의 완료 항목과 다음 미션을 갱신한다.
3. docs/SKILLS.md에는 직접 구현·설명 확인 증거를 연결한다.
4. 프로필 README에는 공개할 수 있는 중요한 변화만 반영한다.
5. 면접 복귀는 INTERVIEW-GATE의 실제 확인 범위에 한정한다.

임의 진행률, 미실행 테스트 PASS, 과거 프로젝트 수치의 재사용은 금지한다.
변경 내용과 근거, 아직 부족한 자료를 제시해줘.
내가 이번 요청에서 게시까지 요청한 경우에만 GitHub에 반영하고 실제 반영 여부를 확인해줘.
```

## 4. 기존 프로젝트 재학습 요청

```text
이 저장소는 현재 면접 활용에서 제외되어 있다.
코드가 있다는 이유로 내가 이해한다고 가정하지 말아줘.
현재 프로젝트에 필요한 개념 하나를 선정하고 작은 재구현 과제를 내줘.
내 코드와 설명을 리뷰하고 다른 입력·작은 기능 변경으로 이해를 확인해줘.
통과한 범위, 증거, 남은 한계를 기록하고 전체 프로젝트를 자동 복귀시키지 말아줘.
```

## 5. 프로젝트 완료 후 정리 요청

```text
이 프로젝트의 코드·실행 기록·평가·본인 기여 자료로 포트폴리오를 정리해줘.
문제 → 직접 구현 → 검증 결과 → 실패와 한계 순서로 작성해줘.
데이터 출처·분할·표본 수·지표·환경·커밋이 없는 수치는 본문 성과로 쓰지 말아줘.
README, 1분 소개, 3분 기술 설명, 예상 질문을 만들되 근거 없는 문장은 제외해줘.
남아 있는 계획은 구현된 기능과 별도로 표시해줘.
```
