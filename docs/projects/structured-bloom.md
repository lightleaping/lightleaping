# Structured Bloom — Streamlit 재구현

[작업 저장소](https://github.com/lightleaping/structured-bloom-streamlit) · [첫 미션](https://github.com/lightleaping/structured-bloom-streamlit/blob/main/docs/MISSION-01.md)

상태: Python 기반 재구현 준비. 면접 활용: 제외, 새 버전 직접 구현·검증 후 재검토.

## 목표와 범위

현재 기분과 사용 가능한 시간을 입력받아 회복 활동을 추천하고, 추천 이력·활동 완료·피드백을 관리합니다.

기존 웹 MVP는 기능 참고 자료입니다. 새 버전은 Streamlit으로 화면을 구현하며 React·JavaScript·TypeScript 직접 개발을 범위에 넣지 않습니다. 코디 서비스와 독립된 프로젝트입니다.

기존 구현·화면·기여·수치를 새 버전의 완료 실적으로 옮기지 않습니다. 기존 원본을 덮어쓰지 않고 별도 작업 범위에서 재구현합니다.

## 구현 단계

- [ ] 기분·시간 입력 → 활동 하나 추천 → 결과 표시.
- [ ] 추천 로직과 활동 데이터를 화면 코드에서 분리.
- [ ] 추천 이력·활동 완료·피드백 저장.
- [ ] FastAPI로 추천·기록 기능 연결.
- [ ] 추천 설명 생성 등 실제 AI 기능 하나 추가.
- [ ] 기존 규칙 방식과 비교 평가.
- [ ] 입력 검증, 실패 처리, 중복 저장 방지, 실행 문서 정리.

## 기술 선택 계획

화면은 Streamlit, 추천 로직은 Python 모듈, API는 FastAPI를 계획합니다. 저장은 SQLite에서 시작하고 PostgreSQL 전환은 필요와 진도에 따라 결정합니다. 현재 이 기술들이 모두 새 버전에 구현됐다는 뜻은 아닙니다.

계획 구조: Streamlit → FastAPI → 추천/기록/피드백 서비스 → DB 및 AI 호출.
첫 미션에서는 별도 서버 없이 작은 추천 함수를 화면에 연결할 수 있습니다.

## 평가 기준

- 입력 기분·시간 조건에 맞는 활동인가.
- 화면 재실행으로 요청과 기록이 중복되지 않는가.
- 다른 세션의 사용자 기록이 섞이지 않는가.
- AI 실패 시 상태를 안내하고 재시도/기본 추천을 제공하는가.
- AI 추가가 추천 설명·조건 준수에 어떤 차이를 주는가.

## 현재 결과

새 Streamlit 버전: 실행 미검증. AI 연동: 미검증. 작업 저장소 개설 완료. 현재 준비 문서만 있으며 실행 코드·데모는 아직 없습니다.

첫 미션 완료 기준: 기분·시간 입력으로 활동을 표시하고, 추천 로직과 화면의 역할을 설명합니다.
