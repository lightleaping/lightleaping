# 면접 활용과 재학습 기준

기존 GitHub에 저장소·코드·README·성능 수치가 있어도 현재 본인이 설명할 수 있는 역량으로 간주하지 않습니다. 모든 기존 프로젝트를 면접 활용에서 우선 제외하고 다음 중 하나로 관리합니다.

- **재학습 후보:** 필요한 개념을 직접 재구현한 뒤 다시 검토.
- **면접 제외:** 자료는 보존하되 대표 프로젝트·지원서·면접 답변에 사용하지 않음.

새 프로젝트도 완료 기준을 통과하기 전에는 진행 중인 계획으로만 소개합니다.

## 복귀 기준

- [ ] 문제와 입력·출력을 본인 말로 설명한다.
- [ ] 핵심 코드를 직접 다시 작성하거나 구조를 바꾸어 구현한다.
- [ ] 함수·모델·데이터 흐름과 선택 이유를 설명한다.
- [ ] 준비된 환경에서 실행을 재현하고 실패 로그를 해석한다.
- [ ] 새로운 작은 기능 변경 또는 오류 수정 과제를 수행한다.
- [ ] 데이터 출처, 분리, 지표, 평가 한계를 설명한다.
- [ ] 참고 코드·팀원·AI 도움과 본인 기여를 구분한다.
- [ ] 확인 날짜·대상 커밋·질문·결과가 기록되어 있다.

전체 프로젝트를 자동으로 복귀시키지 않습니다. 전처리와 학습 루프만 확인했다면 그 범위만 설명 가능한 역량으로 표시합니다. 서비스 과제에서는 평가 항목을 API·저장·실패 처리 검증에 맞춥니다.

## 면접 문장

준비 단계: “실제 상품 이미지로 코디 보드를 만드는 프로젝트를 준비하고 있으며, 현재 상품 데이터 연결부터 직접 구현하고 있습니다.”

검증 후 양식: “저는 [문제]를 해결하기 위해 [직접 구현한 부분]을 작성했습니다. [평가 조건]에서 [확인한 결과]를 얻었고, [한계]를 분석했습니다.”

대괄호는 검증한 내용으로만 채웁니다. 이전 README의 수치를 복사하지 않습니다.
