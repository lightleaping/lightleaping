# 공통 기록 양식

아래 양식을 복사해 프로젝트별 기록으로 사용합니다. 빈칸을 임의로 채우지 않고 미확인·미실시를 명시합니다.

## 미션 기록

```text
미션 ID / 날짜:
프로젝트 / 목표:
완료 기준:
내가 직접 구현한 파일·함수:
참고 코드와 AI 도움:
실행 환경 / 명령 / 입력:
실제 출력 / 로그 위치:
실패와 수정:
내 설명과 리뷰 결과:
작은 변경 과제와 결과:
코드·커밋·공개 가능 결과물:
상태: 준비 / 구현 중 / 실행 확인 / 이해 확인
다음 미션:
```

```text
출처와 사용 조건:
대상 / 표본 수 / 변수 / 단위:
라벨의 의미와 생성·검수 방법:
정상 동작 가정:
오류 생성 방식 / 강도 / 시작·끝 / 난수 시드:
실제 사례에서 확인한 사실:
직접 추가한 가정:
Train / Validation / Test 분리 단위:
중복·누수 확인:
모델·Agent에 제공할 정보:
평가자만 볼 정답:
한계:
```

```text
문제:
고려한 선택지:

내가 직접 구현한 범위:
기존·외부·팀 코드와 구별:

```

## 이상탐지 논문 구성안

1. 초록: 문제·방법·실제 측정 결과·한계. 결과가 없으면 초안이라고 표시.
2. 서론: 왜 해당 오류와 분석 문제가 필요한가.
3. 관련 연구·발생 사례: 실재하는 출처와 적용 범위.
4. 시스템·시나리오: 정상 동작, 변수, 오류 가정, Agent 역할.
5. 실험 설계: 분할, 정답 은닉, 기준 모델, 평가 정의, 반복 조건.
6. 결과: 탐지·원인 분석·설명·보고서 성능을 분리.
7. 논의: 실패, 합성 데이터 한계, 일반화 범위, 구성요소 효과.
8. 결론: 실제 확인한 내용과 후속 과제.
9. 참고문헌·부록: 코드 버전, 설정, 데이터 카드, 보고서 예시.

## 사건별 자동 보고서의 계획 필드

사건 ID, 관측 기간, 이상 구간, 점수, 원인 후보·순위, 관측 근거, 불확실성, 대응 제안, 분석 도구/모델 버전, 생성 시각, 실패·누락 항목.

평가 전용 정답은 사건 보고서 생성 입력에 넣지 않습니다. 자동 보고서의 원인 후보와 평가용 정답을 별도로 비교합니다.
